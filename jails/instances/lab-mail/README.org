#+TITLE: lab-mail

The mail hub for the lab-devel list. lab-mail holds the list, synced
both ways with Fastmail, takes posts over SMTP, and serves the list
over IMAP to every host that uses it. It holds the Fastmail
credentials and is the only thing that talks to Fastmail. spec.org
has the design.

* rights
Who may do what to the list. Everything below follows from these
rules.
- Anyone who can reach lab-mail may post to the list over SMTP, with
  no login. Posting only adds a message. It cannot change or remove
  one already there.
- Anyone may read the list over IMAP. Any user name logs in with any
  password, and that login may list, fetch, search, and IDLE, and
  nothing else. It cannot set flags, append, copy, move, or expunge,
  so it cannot archive or delete a message, or mark one read for
  anyone else. An agent logs in as its own address, such as
  =claude@p7x.dev=.
- Two logins may change the list: =pat@p7x.dev= and =mbsync=. Each
  must give the password in =imap-users=, and a wrong one fails. Pat
  archives and deletes, and mbsync syncs with Fastmail. Only mbsync
  may create a folder, one it finds on Fastmail.
- Dovecot's ACL enforces these rights, not file permissions. Dovecot's
  user can write the whole maildir, so a fault in =dovecot-acl= or in
  the passdbs of =dovecot.conf= would let every login change the list.

* how it works
lab-mail shares beastie's addresses (=ip4 = inherit=), like the
client jails. Its services listen on 127.0.0.1, which every such jail
on beastie reaches and nothing off beastie does. Clients reach them
over that loopback, never through a shared filesystem.

Two host directories are mounted into the jail, and into no other:
- =/jails/data/lab-mail/secrets= at =/data/secrets=, read-only. It
  holds the secrets, which setup describes.
- =/jails/data/lab-mail/mail= at =/data/mail=, read-write. It holds
  the list and the mail state, which survive a rebuild of the jail.

Dovecot is the only program that writes the list. Every change to it,
a post, a sync from Fastmail, or a move or deletion by Pat, goes
through Dovecot, as the user =vmail=.

** posting
#+BEGIN_EXAMPLE
client --SMTP--> OpenSMTPD 127.0.0.1:2525 --LMTP--> Dovecot --> INBOX
#+END_EXAMPLE

rc(8) starts OpenSMTPD when the jail starts; its config is
=/usr/local/etc/mail/smtpd.conf=. A client connects without logging
in. OpenSMTPD sorts each recipient:
- =lab-devel@p7x.dev=, =lab@lists.p7x.dev=, and
  =freebsd-ports@lists.p7x.dev= are delivered to the list. The table
  =list= in =smtpd.conf= lists them. A message to two of them lands
  on the list twice, once for each.
- =pat@p7x.dev=, =pat@patmaddox.com=, and =claude@p7x.dev= are
  accepted and discarded, since everyone reads their mail on the
  list. A reply to all then lands on the list once. The table =known=
  in =smtpd.conf= lists them.
- Any other recipient is refused with a 5xx reply, and the client
  abandons the whole message.

Before it answers the client's DATA, OpenSMTPD parses the header. It
refuses a message with a header line that is neither a field nor the
continuation of one, while the client is still connected. It adds a
Message-ID and a Date to a message that lacks them, as it does on any
loopback listener.

OpenSMTPD then queues the message and hands it to Dovecot over LMTP,
on the socket =/var/run/dovecot/lmtp=, which only =vmail= may open.
LMTP delivers it to INBOX. OpenSMTPD never opens the maildir. If
Dovecot is stopped, the message waits in OpenSMTPD's queue and lands
when Dovecot is back. The next sync carries it to Fastmail.

OpenSMTPD never relays. Nothing posted leaves lab-mail except as a
message that mbsync copies into a Fastmail folder.

** syncing with Fastmail
#+BEGIN_EXAMPLE
imap.fastmail.com:993 <--IMAPS--> mbsync <--IMAP--> Dovecot 127.0.0.1:2143
#+END_EXAMPLE

List mail lands in INBOX on Fastmail, and =Archive= is Fastmail's own
archive folder. Once a minute, the jail's cron(8) runs the sync job,
=/usr/local/libexec/lab-mail/sync=, as the user =mbsync=. The job is
in =/etc/cron.d/lab-mail=, not in a crontab, so =crontab -l= does not
show it. lockf(1) skips a run while the previous one is still going.

The sync job runs mbsync with =/usr/local/etc/mbsyncrc=. It logs in to
Fastmail with =mail-creds=, and to Dovecot as =mbsync= with
=mbsync-imap=, and syncs INBOX, =Next=, =Later=, and =Archive= both
ways: new messages, flags, moves, and deletions. Any other folder of
the Fastmail account stays there. The folders come from Fastmail. A
folder of the list that lab-mail lacks, such as =Next= at the first
sync, is created on lab-mail, and no folder is ever created on
Fastmail. mbsync never expunges a message on either side. A message
expunged on one side is only marked =\Deleted= on the other, so
Fastmail keeps every message ever posted, and a mistaken deletion on
lab-mail can be undone from there. mbsync keeps its sync state in
=/data/mail/mbsync=.

** reading
#+BEGIN_EXAMPLE
/data/mail/maildir --> Dovecot 127.0.0.1:2143 --IMAP--> client
#+END_EXAMPLE

rc(8) starts Dovecot when the jail starts; its config is
=/usr/local/etc/dovecot/dovecot.conf=. It serves the maildir as the
mailboxes INBOX, =Next=, =Later=, and =Archive=, as on Fastmail. It
creates none of them. Each comes from Fastmail. Every login sees the
same mailboxes, and runs as =vmail=, which keeps Dovecot's indexes in
=/data/mail/dovecot=. What each login may do is in =dovecot-acl=, as
rights describes.

Reading and posting keep working while Fastmail is down.

** logs
Each service logs through syslogd(8) in the jail, to a file of its
own under =/var/log/lab-mail/=, and all of them to =/var/log/maillog=:
- =smtpd.log=: each session, with the client, the envelope, each
  recipient's fate, and each delivery to Dovecot.
- =sync.log=: each sync that moved mail, with mbsync's counts, and
  every sync failure.
- =dovecot.log=: each IMAP login, each LMTP delivery, and every error.

A sync that moves nothing logs nothing, so a quiet =sync.log= is
normal. The routing is in =/etc/syslog.d/lab-mail.conf=, and
newsyslog(8) rotates the files daily and keeps a week. From beastie:
#+BEGIN_EXAMPLE
doas tail -f /jails/instances/lab-mail/var/log/lab-mail/sync.log
#+END_EXAMPLE

* setup
The operator stores three secrets on the host, in
=/jails/data/lab-mail/secrets/=. They never enter the repo. The jail
mounts the directory read-only at =/data/secrets=, and no other jail
mounts it.
- =mail-creds= holds two lines: the Fastmail login on the first, and
  an app password with IMAP access on the second. Each line is taken
  whole, whatever it contains. Only mbsync reads it.
- =mbsync-imap= holds the password of mbsync's Dovecot login. Only
  mbsync reads it.
- =imap-users= holds the logins that may change the list, one per
  line as =login:hash=: =pat@p7x.dev= and =mbsync=. Only Dovecot's
  auth process, as the user =dovecot=, reads it.

Pat keeps the password for =pat@p7x.dev= on beastie, in
=~/.config/lab-mail/password=, which only he can read. lab-mail holds
only its hash. Hash each password with Dovecot's doveadm, which
prompts for it:
#+BEGIN_EXAMPLE
doas jexec lab-mail doveadm pw -s BLF-CRYPT
#+END_EXAMPLE

The host knows each reader only by number: 15102 is mbsync, from
=instance.conf=, and 143 is dovecot, from the package:
#+BEGIN_EXAMPLE
mkdir -p /jails/data/lab-mail/secrets
cd /jails/data/lab-mail/secrets
printf '%s\n' 'login@example.com' 'app-password' > mail-creds
printf '%s\n' 'mbsync-password' > mbsync-imap
printf '%s\n' 'pat@p7x.dev:{BLF-CRYPT}...' 'mbsync:{BLF-CRYPT}...' > imap-users
chown 0:0 .
chmod 0711 .
chown 0:15102 mail-creds mbsync-imap
chown 0:143 imap-users
chmod 0640 mail-creds mbsync-imap imap-users
#+END_EXAMPLE

=/jails/data/lab-mail/mail/= holds the list and the mail state. The
jail mounts it read-write at =/data/mail=. The operator creates it and
its subdirectories before the jail first starts, owned by number from
=instance.conf=: 15102 is mbsync, 15103 is vmail.
#+BEGIN_EXAMPLE
install -d -m 0755 /jails/data/lab-mail/mail
install -d -o 15103 -g 15103 -m 0700 /jails/data/lab-mail/mail/maildir
install -d -o 15103 -g 15103 -m 0700 /jails/data/lab-mail/mail/dovecot
install -d -o 15102 -g 15102 -m 0700 /jails/data/lab-mail/mail/mbsync
#+END_EXAMPLE

=maildir= and =mbsync= must start empty. A maildir that mbsync wrote
itself, before Dovecot held the list, must be emptied, along with its
=mbsync= directory: mbsync starting with no sync state would copy
every message already on both sides to the other side again.

Folders come from Fastmail, so the operator creates =Next= and =Later=
on Fastmail, in its web interface, before the first sync. INBOX and
=Archive= are there already.

* operate
Like the other instances; see =jails/README.org=:
#+BEGIN_EXAMPLE
just build
just install
just start
#+END_EXAMPLE

The build starts the jail before it installs the config, so restart
the jail after a build that changes the config.

** import the jj maildir
The list's history is in the jj maildir on the =mail= bookmark. Once
lab-mail's first sync has pulled the list from Fastmail, the operator
imports that maildir into INBOX once, from beastie, as =pat@p7x.dev=.
The next sync carries it to Fastmail. mbsync renames each file it
syncs, so it reads a copy, never the jj working copy:
#+BEGIN_EXAMPLE
cp -R ~/lab/mail.jj/maildir /tmp/list-import
mkdir /tmp/list-import-state
cat > /tmp/list-import.rc <<'EOF'
IMAPAccount lab-mail
Host 127.0.0.1
Port 2143
TLSType None
AuthMechs LOGIN
User pat@p7x.dev
PassCmd "cat ~/.config/lab-mail/password"

IMAPStore lab-mail
Account lab-mail

MaildirStore import
Path /tmp/
Inbox /tmp/list-import

Channel import
Far :lab-mail:INBOX
Near :import:
Sync Push New
Create None
Expunge None
Remove None
CopyArrivalDate yes
SyncState /tmp/list-import-state/
EOF
mbsync -c /tmp/list-import.rc import
#+END_EXAMPLE

A message that is already on Fastmail and in the jj maildir lands
twice. notmuch indexes both files under the one Message-ID, so a
thread shows it once.

* check
=just check= checks that lab-mail is set up and running. It prints
one line per check, ok or FAIL, and exits non-zero if any check
fails:
#+BEGIN_EXAMPLE
$ just check
ok the jail is running
ok /data/secrets/mail-creds exists
...
FAIL OpenSMTPD is running
FAIL OpenSMTPD accepts connections on 127.0.0.1:2525
...
#+END_EXAMPLE

It checks the jail, that each secret is present and readable by its
reader and no other service user, the owners of the mail state
directories, that syslogd, cron, OpenSMTPD, and Dovecot are running,
that OpenSMTPD and Dovecot accept connections, that OpenSMTPD's queue
holds no message older than five minutes, that a sync succeeded
within the last five minutes, and that the log files exist. The sync
job touches =/data/mail/mbsync/last-sync= after each successful run,
so a quiet list still passes. The check only reads, so it is safe to
run at any time; =/usr/local/libexec/lab-mail/check= in the jail does
the work.

When a check fails, the service's log under =/var/log/lab-mail/=
usually says why.
