#+TITLE: yolo-jail - jails for agents on yolo

yolo-jail creates yolo's jails from their templates' packages.

* Build

: redo yolo-jail.pkg

* Install

Copy =yolo-jail.pkg= to yolo, then as root:

: pkg add yolo-jail.pkg

* Repository

: doas yolo-pkg-init

=yolo-pkg-init= makes =zroot/pkg=, mounted at =/pkg=, and
=zroot/pkg/yolo= in it, those that are missing. =/pkg/yolo= holds the
pkg repository of the templates' packages. =zroot/pkg= has =exec=off=
and =setuid=off=, so nothing there runs. =/pkg/yolo= belongs to the
user who ran =doas=, who copies the repository there. Root never
writes it.

* Create

: yolo-jail-create <name> <template>

=yolo-jail-create= makes =zroot/jails/instances/<name>= with FreeBSD's
base and the template's package, =yolo-<template>=, installed, unless
the dataset exists. A jail's config runs it as =exec.prepare=, so the
first start creates the jail. Only the admin destroys a jail, to start
it over.

It builds the jail in =zroot/jails/instances/<name>.new= and renames
that to =<name>= once it is done, so a jail that exists is complete.
A =<name>.new= left by a failed run was never started, so it destroys
that and begins again. pkg's cache, =/var/cache/pkg= in the new root,
is =zroot/jails/pkg-cache= mounted there while it works, so a jail
gets the packages the last one downloaded, and only what is new is
fetched. It is outside the BE, and no jail sees it. pkg checks each
cached package against its repository's checksum before installing
it, and =pkg clean= drops those the repositories no longer offer, so
it holds only current packages. It installs base with =pkg --rootdir=, from
yolo's own repository config. It copies in yolo's =resolv.conf=, and
adds =yolo-pkg-repos= from =/pkg/yolo= with =pkg --rootdir= too, since
it runs no scripts, so pkg in the root has the jail's repository
configs. Then it mounts devfs and =/pkg/yolo= in the new root, and
installs =yolo-<template>= with =pkg --chroot=, so its install scripts
run against the jail's own tools and accounts. It refuses to start
unless =/pkg/yolo= holds =yolo-pkg-repos=.

Those scripts run as yolo's root in a chroot, which is no jail. That
is safe only because the root is new, and holds nothing but what
FreeBSD's repositories and yolo's put there. yolo never runs pkg on a
root that a jail has run in, so an upgrade goes through =jexec=.

: yolo-jail-create-mountpoints <name> <path> ...

=yolo-jail-create-mountpoints= makes each =<path>= under the jail's
root, and each directory on the way that is missing, so that
jail.conf can mount something there. A jail's config runs it as
=exec.prepare= for every mount it makes in the jail: the repository at
=pkg/yolo=, and the git repos at =git/<owner>/<repo>.git= and
=git/agent=. So a jail made before one of them was added gets its
mountpoint too. The jail's root may have turned a directory on the
way into a symlink, which mkdir would follow out of the jail, so it
refuses those.

* Repos

: doas yolo-git-init <owner>/<repo>:<branch> ...

=yolo-git-init= makes each upstream repo that jails clone,
=/git/<owner>/<repo>.git=, and the datasets that hold it, those that
are missing. =zroot/git=, mounted at =/git=, has =exec=off= and
=setuid=off=, so nothing there runs. =zroot/git/<owner>= holds an
owner's repos. Both it and the repos belong to the user who ran
=doas=, and it makes the repos as that user, so no git runs as root.

It points each repo's =HEAD= at =<branch>=, the branch a clone checks
out, every time it runs, so changing the branch and running it again
changes it on yolo. It prints each repo it makes and each =HEAD= it
changes.

* Git

: yolo-jail-git <name> <owner>/<repo>

=yolo-jail-git= makes =zroot/git/jails/<name>=, if it is missing,
which holds the jail's own repos and belongs to the agent, uid 15000.
It refuses if the jail's upstream repo, =/git/<owner>/<repo>.git=, is
missing; =yolo-git-init= makes it. A jail's config runs it as
=exec.prepare=. =yolo-jail-create-mountpoints= makes the repos'
mountpoints in the jail.

: yolo-jail-repo <name> <owner>/<repo>

=yolo-jail-repo= makes a bare repo of the jail's agent's own, at
=/git/agent/<owner>/<repo>.git=, for its work, unless it exists. It
runs git in the jail, as the agent, so nothing the jail has written
runs on yolo. A jail's config runs it as =exec.poststart=, so every
start makes it if it is missing.
