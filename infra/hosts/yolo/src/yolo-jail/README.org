#+TITLE: yolo-jail - jails for agents on yolo

yolo-jail creates yolo's jails from their templates' packages, and
upgrades them.

* Build

: redo yolo-jail.pkg

* Install

yolo's BE carries it. It depends on yolo-pkg, in =src/yolo-pkg=,
whose repository, =/pkg/yolo=, it creates jails from. To install a
newer one without a new BE, on beastie in =infra/hosts/yolo=:

: just install-pkg

It syncs the package, with the rest of =/pkg/yolo=, to yolo, and
installs it from there. A yolo without yolo-pkg needs
=just pkg-init= first.

* Init

: yolo-jail-init <name>

=yolo-jail-init= sets a jail up, so that starting it makes nothing.
It looks the jail's template and repos up in
=/usr/local/share/yolo-jails/instances=, from the yolo-jails package.
Then it runs =yolo-jail-git=, =yolo-jail-data=, =yolo-jail-create=,
and =yolo-jail-create-mountpoints=, below, and makes
=zroot/jails/instances/<name>/data=, the dataset the jail runs itself,
with =jailed=on=. Each makes only what is missing, so running it again
gives a jail whatever a newer yolo-jail adds. It refuses while the
jail runs, since the jail could then change its root under
=yolo-jail-create-mountpoints=.

A jail's config refuses to start the jail until its root exists, and
says to run =yolo-jail-init=.

* Create

: yolo-jail-create <name> <template>

=yolo-jail-create= makes =zroot/jails/instances/<name>= with FreeBSD's
base and the template's package, =yolo-<template>=, installed, unless
the dataset exists. =yolo-jail-init= runs it. Only the admin destroys
a jail, to start it over.

It builds the jail in =zroot/jails/instances/<name>.new= and renames
that to =<name>= once it is done, so a jail that exists is complete.
A =<name>.new= left by a failed run was never started, so it destroys
that and begins again. pkg's cache, =/var/cache/pkg= in the new root,
is =zroot/jails/pkg-cache= mounted there while it works, so a jail
gets the packages the last one downloaded, and only what is new is
fetched. It is outside the BE, and no jail sees it. pkg checks each
cached package against its repository's checksum before installing
it, and =pkg clean= drops those the repositories no longer offer, so
it holds only current packages. It installs base with =pkg --rootdir=, from
yolo's own repository config. It copies in yolo's =resolv.conf=, and
adds =yolo-pkg-repos= from =/pkg/yolo= with =pkg --rootdir= too, since
it runs no scripts, so pkg in the root has the jail's repository
configs. Then it mounts devfs and =/pkg/yolo= in the new root, and
installs =yolo-<template>= with =pkg --chroot=, so its install scripts
run against the jail's own tools and accounts. It refuses to start
unless =/pkg/yolo= holds =yolo-pkg-repos=.

Those scripts run as yolo's root in a chroot, which is no jail. That
is safe only because the root is new, and holds nothing but what
FreeBSD's repositories and yolo's put there. yolo never runs pkg on a
root that a jail has run in, so an upgrade goes through =jexec=.

: yolo-jail-create-mountpoints <name> <path> ...

=yolo-jail-create-mountpoints= makes each =<path>= under the jail's
root, and each directory on the way that is missing, so that
jail.conf can mount something there. =yolo-jail-init= runs it for
every mount the jail's config makes: the repository at =pkg/yolo=, and
each git repo at =git/<owner>/<repo>.git= and =git/agent=, and the
agent's Claude Code settings at =home/agent/.claude=. The jail's
root may have turned a directory on the way into a symlink, which
mkdir would follow out of the jail, so it refuses those. It refuses a
=<path>= that is absolute or has a =.= or =..= in it, though a part of
it may start with a dot.

* Upgrade

: yolo-jail-upgrade [-a] <name>

=yolo-jail-upgrade= upgrades the =yolo-= packages in a running jail,
and whatever their new versions need. With =-a=, it upgrades all of
the jail's packages, including FreeBSD's base. It runs pkg in the
jail with =jexec=, so nothing the jail has written runs on yolo.
Nothing runs it on its own.

A jail's base must be no newer than yolo's. So it first has pkg in the
jail work out the upgrade without doing it, and fails if any =FreeBSD-=
package would end up newer than yolo's base, the version of yolo's own
=FreeBSD-runtime=, which holds =freebsd-version=. It names each such
package, and changes nothing. Otherwise it upgrades from the catalogue
it checked, without updating it, so what it checked is what it
installs. The check guards against upgrading too soon, not against the
jail: the jail's root could change its own pkg.

* Repos

: doas yolo-git-init <owner>/<repo>:<branch> ...

=yolo-git-init= makes each upstream repo that jails clone,
=/git/<owner>/<repo>.git=, and the datasets that hold it, those that
are missing. =zroot/git=, mounted at =/git=, has =exec=off= and
=setuid=off=, so nothing there runs. =zroot/git/<owner>= holds an
owner's repos. Both it and the repos belong to the user who ran
=doas=, and it makes the repos as that user, so no git runs as root.

It points each repo's =HEAD= at =<branch>=, the branch a clone checks
out, every time it runs, so changing the branch and running it again
changes it on yolo. It prints each repo it makes and each =HEAD= it
changes.

* Git

: yolo-jail-git <name> <owner>/<repo> ...

=yolo-jail-git= makes =zroot/git/jails/<name>=, if it is missing,
which holds the jail's own repos and belongs to the agent, uid 15000.
On every run it mounts the dataset if it is not mounted, and gives it
to the agent. Otherwise the jail's =/git/agent= would be the
root-owned directory beneath it, and the agent's repo could not be
made there. So if a jail fails to start with =cannot mkdir
/git/agent/...: Permission denied=, stop it and run =yolo-jail-init=
again. It refuses if any of the jail's upstream repos,
=/git/<owner>/<repo>.git=, is missing; =yolo-git-init= makes them.
=yolo-jail-init= runs it, and =yolo-jail-create-mountpoints= makes
the repos' mountpoints in the jail.

: yolo-jail-repo <name> <owner>/<repo>

=yolo-jail-repo= makes a bare repo of the jail's agent's own, at
=/git/agent/<owner>/<repo>.git=, for its work, unless it exists. It
runs git in the jail, as the agent, so nothing the jail has written
runs on yolo. A jail's config runs it as =exec.poststart=, once for
each of the jail's repos, so every start makes those that are missing.

* Data

: yolo-jail-data <name>

=yolo-jail-data= makes =zroot/jails/data/<name>=, if it is missing,
under which go the datasets that hold what a jail keeps across resets.
=zroot/jails/data= has =setuid=off=. =yolo-jail-init= runs it.

It also makes =zroot/jails/data/<name>/claude=, if it is missing, the
agent's Claude Code settings and credentials, which belongs to the
agent, uid 15000. On every run it mounts it if it is not mounted, and
gives it to the agent, as =yolo-jail-git= does.
=yolo-jail-create-mountpoints= makes =/home/agent/.claude= in the
jail, and a jail's config mounts it there read-write.
