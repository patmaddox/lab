* Figure out some kind of TODO -> agent -> DONE workflow
This is a tough one... but basically I think it's worth thinking of my
todo.org as being a simple queue of stuff that I'm interested in
doing. It's not really a queue - it's just a good way of organizing
information.

The challenge is when it comes to splitting it up. Obviously I can't
rebase it very easily if I have agents chopping it up and stuff.

The core idea here is that a heading represents some sort disturbance
to the current system. I want to run an agent that will resolve that
disturbance by taking the information and proposing a commit for me to
integrate.

Essentially what I'm thinking of is something like this:

- todo
- next
- wip
- review
- done

Review can go back into my todo file (or more likely to doing - but I
put it in todo and dispatch it to doing). An agent selects which one
to work on, moves it to wip. When it's ready for my review, it gets
moved to review. I can then accept it and mark it as done.

So this thing likely has a few components to it. The first is an emacs
command that takes a heading, and dispatches it to a unique file name
in next.

The next is agent, which selects the next item to work on, moves it to
wip (or maybe just sets the status?), and dispatches it to an agent. I
think moving it to wip is simpler because it's deterministic. When the
agent completes its work, it moves it into review.

Each stage rebases off the next. In fact, these can probably all be
stacked branches off of each other? At least next and wip will be. Or
actually... each item is its own branch, or has its own branches. So
when it's being worked on, the branch will be wip/abc123. When it's
done, it'll be review/abc123.

The agent will periodically rebase everything off of trunk, and all I
have to do to integrate is rebase off of review/whatever.

There's another rule that if I push a commit on top of review/abc123,
the agent looks at any commits that are authored by me on top of their
work as feedback, integrate it, and try again.

I then have a pretty simple view of work to review, which is something
like =bookmark('review/*') ~ ::mine()=. That will show any series of
commits that I haven't left a review on top of. Review it, and when
there's nothing left to say, I'm done.

The reviews can even have versions so I can interdiff them.

Analyze =todo.org= and =fieldstones.org= and produce a concise
report with three categories, showing the top 5-10 items in each:
1. *Ready to pursue* — well-defined, feasible, high value.
   These should be worked on soon.
2. *Worth advancing* — promising but needs more definition or
   groundwork. Invest in sharpening these.

   developed in a while. Either push them forward or let them go.
Score items on definition, feasibility, and value. Keep the report
short enough to scan in a minute.
