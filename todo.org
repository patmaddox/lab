* TODO Document command progression maturity levels
Commands evolve through stages as they prove useful:
1. Description in a Claude skill (SKILL.md) — Claude interprets instructions
2. Script embedded in Claude skill — reusable but coupled to skill
3. Standalone script — usable outside Claude
4. Just command — discoverable via =just -l=, composable
5. First-class command — standalone binary/script on PATH, no just dependency
6. Emacs command — streamlines multi-step terminal workflows with
   state and inspection. Example: =jj submittable= → =jj show foo=
   → =jj submit foo= becomes a single emacs command that shows the
   top of the submittable stack, lets you inspect, and submits.
Each stage adds independence from the scaffolding that preceded it.

This progression is the spectrum from creativity to engineering.
LLMs are non-deterministic — great for exploring ideas and bringing
them to life. As an idea proves useful, promote it through stages
that add determinism: from a skill description (LLM interprets
freely) to a script (deterministic). Science explores what's
possible, engineering makes it reliable and rigorous. Command
promotion is the mechanism for that transition.

* TODO Write about commits as corpus, not DAG
We used to focus on producing a specific history — a DAG. Now we
produce a corpus of commits and use tools (submit, promote, review,
feedback) to flow them through to delivery. The DAG is an output of
the process, not an input we craft by hand.

This is Weinberg's Fieldstone Method applied to code (and prose and
ideas). Collect stones — commits, notes, fragments — as they come.
When it's time to build, select the ones that fit and assemble them.
The pipeline (submit → review → promote) is the assembly process.

The =/todo= workflow makes this literal: I speak an idea to Claude
(collecting the stone), and the LLM figures out where it fits —
updating an existing entry or creating a new one (building the wall).
The human collects, the LLM places.
* TODO Write about using jj to manipulate the git DAG
jj treats commits as malleable objects that can be rebased, split,
squashed, and reordered freely. The git DAG is just a serialization
format — jj lets you reshape it without the ceremony git requires.
* TODO Explore spectrum from single files to RAG for knowledge docs
A single =todo.org= works well — Claude sees the whole file and
finds thematic overlap naturally. But as it grows, it will need to
split into multiple files. At that point Claude loses the ability
to spot connections across files without reading them all. RAG
could restore that by surfacing related docs the way the single
file lets it find related entries. Understand where the breakpoints
are and when to introduce each layer.
* TODO Write about just commands as GenServers for Claude
The =just feedback=, =just review= etc. commands treat Claude like
a GenServer — start a process, pass it state (files + skill prompt),
let it do work, collect the result. The "server" is ephemeral (start
and stop each time), but the caller manages state between calls by
controlling the files and commit graph before handing off. The
interesting part: state management lives in the orchestration layer
(shell scripts, jj), not in the LLM.
* TODO Write about learning from inputs (Code Convos)
To learn from experts, watch their inputs — not just the outputs.
Racing sim players learn by watching someone's steering, braking,
throttle inputs and seeing the results. Same idea applies to code:
observe what someone types, what prompts they give, how they
orchestrate tools, and see what comes out. That's the thesis behind
Code Convos — watch the inputs to someone's system and learn their
craft.

* TODO Write about LLMs as the new Unix
LLMs follow the same patterns as Unix: processes (start, do work,
exit), stdio pipes (prompt in, response out), permissions (tool
access, sandboxing). The just/claude-run.sh workflow is literally
process management. Skills are like shell scripts. The jail is
the permission model. Favorite operating systems: FreeBSD, Elixir
(Erlang/OTP), Emacs — and now LLMs. Each is a platform for building
systems on top of, with its own process model and composition story.
