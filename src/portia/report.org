#+TITLE: portia report

* what it is
=src/portia= is a deterministic harness that drives a language model
through the mechanical parts of porting software to FreeBSD. portia
does no porting itself; it owns the edges - the command, the target
directory, the prompt handed to the model, the check that a port-shaped
result landed, and the commit into the ports tree - and leaves the
porting judgement, including the commit message, to MODEL. It is sclr's
pattern aimed at a concrete domain.

* the commands
Each takes one argument naming a port - an origin =category/port=
(relative to =PORTSDIR=) or a path =.../category/port= to a port dir in
a tree - which portia resolves before the model runs into the origin,
the ports tree, and the port directory:
- =new= :: create a complete port from the origin and free-form detail
  read on stdin - finds the distfile, works out the build system and
  dependencies, mines the ports tree for prior art. Requires =Makefile=,
  =distinfo=, =pkg-descr=.
- =update= :: bump to the newest upstream version and reconcile deps.
  Requires =Makefile=, =distinfo=, =pkg-descr=.

They are the two mechanical phases of a port's life: create and
maintain. Each ends by committing the port into the tree, with a
message the model writes to FreeBSD convention - for =update=, citing
the changelog of every intermediate version. The commit is keyed on the
port directory having uncommitted changes, so work an interrupted run
left on disk is picked up and committed, while a port already at its
desired state is a clean success that leaves the tree untouched.

* the pieces
- =portia= :: the harness. Resolves the port argument (origin or path),
  requires the ports tree to be a jj or git repository (preferring jj),
  assembles the prompt, creates the port directory, invokes MODEL,
  checks the required files landed non-empty, then - when the port
  directory has uncommitted changes - commits the port with the message
  the model wrote.
- =prompts/{new,update}.org= :: the porting knowledge. Kept
  as files, so the prompts - the part that actually knows FreeBSD
  porting - evolve without touching the harness.
- =portia.1=, =portia_test=, =Kyuafile= :: man page and kyua suite.

* why a harness, not a porter
Porting is mechanical but the model's output cannot be trusted blind.
Splitting the work this way lets the deterministic edges be tested with
a stubbed MODEL - argument handling, prompt assembly, the port-shape
post-condition, and the commit - so a bad run fails loudly instead of
leaving a half-built port. The prompts carry the domain knowledge and
are the natural place to improve results.

* status
Complete against the spec: both commands, each a vertical slice
with tests and man page, driving the model and committing its result -
including work an interrupted run stranded on disk, and exiting cleanly
when a port is already at its desired state. Exercised only with a
stubbed model; the prompts have not yet been run against a live model or
checked against a real ports tree.
