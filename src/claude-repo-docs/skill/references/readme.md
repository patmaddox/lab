# A minimum viable README

Write only the sections the project needs, in the repo's format and
heading style. A small tool's README may be ten lines. Drop any
section with nothing true to say, and never leave a placeholder.

1. **Title and lead.** One to three sentences on what this is and why
   someone would use it. This part is explanation.
2. **Status**, only if it is not ready to use, such as experimental or
   deprecated.
3. **Use**, or **Quick start.** The shortest path to a real result,
   with exact commands from the repo. This part is a how-to.
4. **Build and test**, for contributors. Use the repo's own commands.
5. **Reference**, kept short. Options, configuration, and environment
   variables, in a table or list. If a man page, docstrings, or a docs
   site holds the reference, link to it instead.
6. **How it works**, only when a reader would otherwise misuse it or
   ask why. Keep it short, or link to a longer explanation.
7. **Layout**, for a directory that holds several things: one line per
   subdirectory or file that a reader would open.

Don't add badges, license boilerplate, contribution templates, or a
table of contents unless the repo's other READMEs have them.
